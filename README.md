# 杀戮尖塔 2 自动打牌（AstrBot 插件）

让 AI 在《杀戮尖塔 2》里自己打牌：读游戏真实状态、按启发式规则出牌、自动选牌/升级/删牌，
也可以在关键界面交给大模型决策。**战斗不烧 token**——默认整局下来模型的调用次数是 0。

> 依赖游戏侧的一个 mod 暴露本地 HTTP 接口（`STS2-Agent` 或 `STS2_MCP`）。没有 mod 也能装，
> 只是读不到状态。

## 它做什么

- `/sts2 状态`：把引擎返回的一大坨 JSON 压成中文快照（血量/能量/敌人意图/手牌/地图/奖励…），
  战斗态从 ~800 token 压到 ~120 token
- `/sts2 自动 20`：连续做 20 个决策。战斗用规则层（斩杀、格挡性价比、药水时机、保命、
  先易伤后输出），非战斗接了卡组构筑（缺什么补什么、牌组过厚收紧阈值、营火升级、商店删牌）
- 构筑会认流派：牌组里攒出两张叠力量的牌就往「多段攻击」上补，攒出三张消耗牌就抢「每当消耗」的回报牌，
  有易伤素材就偏好吃易伤的牌；认不出流派时退回「缺什么补什么」
- 事件选项按收益打分（拿遗物/回血/升级加分，花大半金币、塞诅咒、掉血减分），多选删牌界面会点够张数再确认
- 死了自动回主菜单再开一局（一次自动最多重开 3 次）
- 可选：`use_llm=true` 时把选牌/事件/路线交给当前会话的模型；`llm_combat=true` 连战斗也交给它（很贵）

## 安装

仓库根目录就是插件目录（`metadata.yaml` 在根上），三种装法任选：

- **WebUI 在线装**：插件 → 安装 → 填本仓库地址，AstrBot 会自己拉取
- **WebUI 离线装**：下载 release 里的 `astrbot_plugin_sts2_player-*.zip` → 插件 → 从文件安装
- **手动**：把仓库目录改名成 `astrbot_plugin_sts2_player`，放进实例的 `data/plugins/`，重启

装好先在游戏里进到主菜单，再发 `/sts2 状态`；读不到状态时 `/sts2 状态` 会打印排查清单。
开发/测试/打包脚本见 [docs/DEV.md](docs/DEV.md)。

## 指令

| 指令 | 说明 |
|---|---|
| `/sts2` | 当前状态（中文快照） |
| `/sts2 自动 [n]` | 自动打 n 步（默认 `max_steps`） |
| `/sts2 执行 <动作> [json]` | 手动下一个动作，如 `/sts2 执行 end_turn` |
| `/sts2 停` | 停在当前这一步之后 |
| `/sts2 帮助` | 动作名 + 参数速查 |

LLM 工具：`sts2_state`（读状态）、`sts2_action`（下动作），主模型可以在对话里直接玩。

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `sts2_url` | `http://127.0.0.1:15526` | mod 的本地地址（STS2-Agent 是 `8080`；写错会自动试另一个端口） |
| `sts2_timeout_sec` | 20 | 单次请求超时 |
| `operator_ids` | `[]` | 允许操作游戏的人（空 = 所有人） |
| `max_steps` | 40 | 一次自动最多几步 |
| `step_interval_sec` | 0.3 | 两步间隔 |
| `report_every` | 5 | 每几步播报一次 |
| `use_llm` | false | 关键界面问模型 |
| `llm_combat` | false | 战斗也问模型（贵） |
| `potion_hp_ratio` | 0.32 | 血量低于该比例喝药 |
| `block_priority` | 0.15 | 格挡权重（真机建议 0.6） |
| `card_min` | 18 | 选牌阈值 |
| `auto_restart` | true | 死了自动重开一局 |

## 游戏侧怎么准备

1. 订阅 Steam 创意工坊的 **STS2 AI Agent**（或把 release 里 `mod/` 下的
   `STS2AIAgent.dll`、`STS2AIAgent.pck`、`mod_id.json`（重命名为 `STS2AIAgent.json`）
   放进 `<游戏目录>/mods/`）
2. 启动游戏，进到主菜单就有接口：`curl http://127.0.0.1:8080/health`
3. 注意 `STS2-Agent` 声明了 `min_game_version`（0.17.0 要求 `0.111.0`），游戏版本太老会拒绝加载
4. 老的 `STS2_MCP`（15526）也能用，但只支持较旧的游戏版本

## 模型介入实测（use_llm / llm_combat）

`tools/live_llm.py` 会把插件的 `_ask_llm` 真接上 DeepSeek（走插件自己的代码路径：
`render_state` → `LLM_SYSTEM` → `parse_llm_json` → `_auto` 执行），用 `deepseek-chat` 实跑：

| 模式 | 真机最好成绩 | 模型调用 | tokens | 大约花费¹ |
|---|---|---|---|---|
| 默认（战斗交规则层） | 第 14 层 | 80 次 / 260 步 | 70.6k | ≈¥0.25 |
| 默认，另一局 | 第 14 层 | 50 次 / 150 步 | 42.0k | ≈¥0.13 |
| 默认，第三局 | 第 10 层 | 46 次 / 120 步 | 39.8k | ≈¥0.13 |
| 全部交给模型（`--llm-combat`） | 第 5 层 | 45 次 / 200 步 | 49.9k | ≈¥0.19 |
| 回合计划（`--plan`，开思考） | 第 17 层 | 83 次 / 150 步 | 91.7k | ≈¥0.44 |
| 回合计划（`--plan`，关思考） | 第 8~17 层 | 90 次 / 200 步 | 64.6k | ≈¥0.31 |
| 回合计划 + 实际数值（v0.4.7） | 第 13 层 | 132 次 / 240 步 | 99.5k | ≈¥0.48 |
| 规则层（对照） | 第 15~17 层 | 0 次 | 0 | ¥0 |

¹ 按 `deepseek-chat` 输入 ¥2/百万、输出 ¥8/百万粗估，只为给您一个量级。

对比规则层（同一台机器、同一版本）：真机第 15~17 层，**0 token**。
结论：模型能打，但没有比规则层更好，而且贵两个数量级；一旦把战斗也交给它
（`--llm-combat`）成绩反而掉到第 5 层——回合内的取舍它算不过那几条启发式。
它的价值在于「遇到没见过的事件/商店时不会瞎点」，而不是替掉规则层。

模型暴露的典型毛病（都已加护栏，日志里能看到护栏触发）：

- 奖励已经领完还在发 `claim_reward index 0` → 现在按 `available_actions` 和
  `claimable` 过滤掉，改由规则层收尾
- 药水槽满时硬领药水奖励（`All potion slots are full`）→ 同上
- 需要目标的牌忘了带 `target`（`This card requires target_index`）→ 现在按
  `requires_target` / `valid_target_indices` 自动补一个合法目标
- 在自己不负责的界面（菜单、水晶球）乱发动作 → 按界面白名单 `SCREEN_ACTIONS`
  只喂它能用的动作

### 回合计划模式（`llm_combat_plan`）

逐张问模型太贵，所以另有一条「每回合只问一次」的路：模型给整串出牌顺序，
规则层负责执行、按牌名重新定位、失效就作废（`RuleBot.set_plan` /
`_take_plan` / `parse_plan_json`）。

跑通它踩了三个坑，都值得记一笔：

1. **系统提示词和用户提示词打架**：`LLM_SYSTEM` 要求输出
   `{"think","actions","stop"}`，计划模式要求 `{"think","plan"}`。模型（尤其是会
   把思考过程写进正文的那些）会一直在正文里纠结「到底听谁的」，输出一整段英文
   推理而不是 JSON。解法：计划模式换一份专属系统提示词 `PLAN_SYSTEM`。
2. **`max_tokens` 太小**：400 时 JSON 经常被截断成 `{"think":"...","plan":[`，
   解析必然失败。现在计划模式给 800（`llm_max_tokens`）。
3. **没有「本回合已问过」的闸门**：模型返回空计划时每一步都再问一次，160 步烧掉
   144 次调用、16.7 万 tokens。现在按 `(界面, 回合号)` 记账（`plan_asked`），
   一回合只问一次，空计划就整回合交给规则层。

另外关掉模型的思考模式（`thinking: {"type": "disabled"}`）效果立竿见影：
输出 tokens 从约 420/次掉到约 60/次，计划 100% 能解析。

### 把「实际数值」算给模型看（v0.4.7）

模型最大的短板不是不会想，而是**算不动**：`造成6点伤害` 在有 2 点力量时其实是 8，
多段攻击要乘段数，易伤还要 ×1.5。这些它靠文字推，经常推错。

所以状态渲染改成直接喂引擎算好的真值（`dynamic_values[].current_value`）：

```
  #0 藤蔓蹒跚者 61/61 护甲0 [0] 意图：Attack 6x2
  本回合：敌人合计 12 伤 · 现有护甲 0 · 还差 12 点要挡 · 手牌能打 8 伤（最高一张 8）
  手牌：
    [0] 打击 攻击 1费 造成6点伤害。 →实际8伤
    [1] 防御 技能 1费 获得5点格挡。 →实际5挡
```

`_resolved_damage` / `_resolved_block` 优先读 `dynamic_values`（Damage/Block/Hits），
读不到才退回文本解析；`render_state` 再多算一行「敌人合计多少伤 / 还差多少要挡 /
手牌一共能打多少」。计划模式的系统提示词也明确告诉它：这些数字是引擎真值，直接用、别再自己推。

## 已知限制

- 规则层打不过第 1 幕 Boss 很正常：它只会「先易伤再输出」这一种连招，
  不会算力量/敏捷叠加、不会攒牌打爆发；真机最好成绩在第 15~17 层
- 事件/商店只有「关键词打分」级别的判断，遇到全新事件可能选得不好
- 营火/选牌界面的字段做了容错（缺 `index`、缺 `option_id`、只给中文标题都能认），
  但万一引擎又改了结构，`/sts2 状态` 里会看到「停在「营火」，需要人来点一下」
- 只接管「对局内」，菜单/商店手点之外的部分靠 mod 的 action 列表
- 游戏还在 Early Access，接口字段会随版本漂
